# Generic learning memory implementation

20 September 2026. Implements the [approved plan](learning-generic-memory-implementation-plan-2026-09-20.md) against `b57b5fe585d620b337089c1877489da377b3b5c2`. The earlier [investigation](learning-generic-memory-investigation-2026-09-20.md) and [research](learning-generic-memory-research-2026-09-20.md) remain historical evidence, not claims that production already had this behavior.

## Delivered behavior

Optional scoped `knowledge` entries retain useful, agent-authored prose independently of exercises and learner assessments. Only text is required; optional topics route retrieval and source references capture editions. A save replaces supplied entries whole, preserves omitted entries and deletes named null entries. Existing locks, revision conflicts, atomic publication, source protection and no-op receipts remain the publication boundary. Schema 5 remains current; no migration or automatic historical extraction is necessary.

Ordinary context selects complete relevant entries. Exact reads return only requested entries and minimal source locations. A compact index and literal metadata search make retained understanding discoverable after the original activity ends. Independent revision-pinned candidate/evidence cursors avoid repeatedly loading completed evidence streams. Single-course plans share the same selector; multicourse plans include knowledge counts only. Pi and CLI expose these semantics without a new tool, service or storage backend.

The teaching contract asks the agent to retain useful understanding naturally, distinguish reports from verified sources, preserve unresolved uncertainty, and reconcile consequential contradictions. It must read complete entries before replacements and preserve unaffected facts. Routine bookkeeping stays hidden; unchanged follow-ups require neither a write nor another retrieval. No compulsory course map, intake, ontology or reflection pass is added.

## Why the default is 4,096 bytes

The original 2,048-byte proposal was a conservative engineering choice, not an optimum established by research or local measurement. The previous native probe's three revised entries use 1,515 bytes with selection metadata, before source locations. Both proposed defaults fit this sample. The implementation uses **4,096 serialized UTF-8 bytes** to leave more room for qualifications, Unicode and provenance, and exposes the same explicit `knowledge_budget` override on ordinary scoped context, scoped planning and exact reads.

This is a retrieval allowance, not a limit on stored knowledge. The system returns only actual selected content, not padding up to the allowance. It never cuts an entry to fit. Oversized automatic entries remain discoverable and are counted as omitted; exact reads default to 8,192 bytes and report the required size when that is insufficient. Discovery candidates and index pages each have their own 4,096-byte bound. A requested higher allowance is deliberate, without automatic escalation or retries.

These bounds cover the new memory contribution, not observation history, the complete context response, or cumulative model tokens. No universal byte-to-token conversion is claimed. Reused conversation text can still appear in later requests; provider caching and compaction affect actual cost. The canonical skill grew from 8,618 to 9,906 UTF-8 bytes (+1,288); the Pi context-parameter source block grew by 943 bytes. These are source-size diagnostics, not measured serialized prompt-token deltas. Detailed references remain selectively read.

## Verification and rollout

The final full repository gate passed: **766 Python behavior tests and 24 Pi integration tests**, Ruff lint/format, strict mypy on 136 source files, ten import contracts, and unchanged weekly/monthly/yearly rendering fixtures. Independent review identified two concrete retrieval edge cases after the initial gate: Unicode case-fold expansion shifted excerpt positions, and candidate byte accounting omitted the outer wrapper. Both were corrected and independently rechecked, leaving zero open Standards or Spec findings. The focused retrieval suite now has 27 passing tests, including a case-fold expansion query and exact 4,096/4,097-byte candidate-envelope boundaries.

The live store was inspected read-only: one schema-5 record, no existing `knowledge` field collision. No personal record was migrated, rewritten or populated with synthetic notes. The installed `.agents` and `.claude` learning skills resolve to this checkout, and the `study` launcher uses its Python runtime. Fresh sessions load the updated tools and skill; restart an already-open study session once to load the new definitions.

Four fresh native Pi sessions retained the notation and corrected course interpretation after task completion, left state unchanged during an unrelated clarification, and eventually preserved the unresolved source conflict. Structural assertions do not establish full semantic fidelity: one replacement dropped the explicit conflict caveat after a learner-reported lecturer correction, and another lost explicit learner-report attribution. Four invalid save attempts were rejected and recovered; unnecessary source/knowledge reads also occurred. These are observed model limitations despite explicit preservation guidance, not guarantees supplied by the validator. The final source/skill bytes were stable during every native session.

Native synthetic acceptance and final review results are recorded with the accompanying [acceptance bundle](learning-generic-memory-acceptance-2026-09-20/README.md). Deterministic tests establish software behavior; bounded native sessions establish only the observed model behavior. No GUI, Claude-host parity, long-term reliability or learning efficacy is inferred. Search remains literal. A false belief that is never challenged can persist, and an already-running client can retain stale context until it refreshes.
