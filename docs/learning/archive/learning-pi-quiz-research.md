# Pi question integration research

## Verdict

Use one small optional `quiz` tool in the existing Pi extension, with stable choice IDs and no shuffle initially. Ordinary conversation remains the default for explanations and free reasoning; the tool is useful when explicit choice/input capture improves a particular exercise. This is a fresh implementation against installed Pi **0.85.1**, not a transplant of the original three extensions.

## Findings

1. **Original behavior is useful but broader than required.** At pinned commit `7cfd8942f82ab9476e63572387e1fe9bcea5082c`, `quiz.ts` provides single/multiple selection, stable values, Fisher–Yates shuffle, exact-set grading, delayed feedback, “I don't know,” and a supplementary note. It cannot grade a free-text answer. `ask-user-question.ts` separately offers ungraded text, choices, and “Other.” Neither implements an explicit assisted-performance classification. Together with the logger these files total 2,174 lines. [Original quiz](https://github.com/amosblomqvist/learn/blob/7cfd8942f82ab9476e63572387e1fe9bcea5082c/extensions/quiz.ts), [question tool](https://github.com/amosblomqvist/learn/blob/7cfd8942f82ab9476e63572387e1fe9bcea5082c/extensions/ask-user-question.ts).

2. **Retain the current automatic mirror.** `learning/pi.ts` already publishes the active Pi branch to a session-named Markdown note, using the existing Python publisher and Pi's file mutation queue. Extend its projection to recognise this tool's public question and response. The original `md-log.ts` requires linking commands, writes whole files directly, suppresses write errors, and backfills by walking from the last entry rather than asking Pi for its selected branch. None is needed here. [Current mirror](../../../learning/pi.ts), [original logger](https://github.com/amosblomqvist/learn/blob/7cfd8942f82ab9476e63572387e1fe9bcea5082c/extensions/md-log.ts).

3. **Publish before opening the prompt, explicitly.** Inside tool execution: validate inputs → form public question → await existing lesson publication → open input UI. The original quiz emits `onUpdate` before opening its dialog; the callback itself returns no promise, so awaiting the logger's event handler is not an execution barrier. Pi waits for collected update emissions after `execute` resolves. An awaited call to the current publisher makes the ordering concrete. Abort or report publication failure before accepting an answer. This guarantees file publication before input; Obsidian's own repaint timing still needs a visual check. [Pi tool loop](https://github.com/earendil-works/pi/blob/v0.85.1/packages/agent/src/agent-loop.ts), [extension events](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/docs/extensions.md#tool_execution_start--tool_execution_update--tool_execution_end).

4. **Hide answers through an explicit public projection.** Before response, render only the question/context and displayed choices in both Markdown and `renderCall`; never stringify all tool arguments. Keep the answer key/explanation out of pending UI, partial results, and pending Markdown. A collapsed Obsidian callout still contains the answer in the note and is insufficient. Tool-call arguments remain in Pi's private session history; this is a presentation boundary, not secrecy from a user inspecting raw logs. After an attempt, reveal the supplied answer/explanation and mark how feedback was determined. [Original `renderCall` and update projection](https://github.com/amosblomqvist/learn/blob/7cfd8942f82ab9476e63572387e1fe9bcea5082c/extensions/quiz.ts#L903-L990).

5. **Stable IDs and fixed order are sufficient.** Return the selected stable ID, visible label, and displayed position. Preserve the author-provided order, including ordered numerical options; no shuffle API or random-state machinery is required initially. If shuffle is later desired, shuffle once and persist the resulting public order before displaying it; both live output and reconstruction must use that order. Original completed results preserve shuffled labels, but cancelled results omit them and original backfill falls back to the unshuffled arguments. [Original quiz results](https://github.com/amosblomqvist/learn/blob/7cfd8942f82ab9476e63572387e1fe9bcea5082c/extensions/quiz.ts), [original reconstruction](https://github.com/amosblomqvist/learn/blob/7cfd8942f82ab9476e63572387e1fe9bcea5082c/extensions/md-log.ts#L375-L429).

6. **Separate outcome, grading, and assistance.** Capture `answered`, `dont_know`, `skipped`, `cancelled`, and `unavailable` distinctly; optional notes are supplementary to the actual answer. Only an explicit learner skip means skipped: aborts, unavailable UI, or failed publication provide no learning evidence. Carry prior assistance as supplied context plus learner-reported assistance if offered; a missing field must not establish independent recall. Exact choice matching is deterministic against the supplied key, not proof that the generated key or explanation is scientifically correct. Free reasoning remains ungraded by the tool and is evaluated in the tutor's normal next response. [Existing learning evidence policy](../../../learning/skills/learn/SKILL.md), [original deterministic matcher](https://github.com/amosblomqvist/learn/blob/7cfd8942f82ab9476e63572387e1fe9bcea5082c/extensions/quiz.ts#L219-L224).

7. **Use native Pi lifecycle and persistence.** `message_end` handlers run before the message is appended: retain the current pending-message overlay, now including supported tool results. `tool_call` sees the current assistant tool-calling message already persisted. Rebuild from `ctx.sessionManager.getBranch()`, pairing by tool-call ID; include unanswered questions without inventing responses. Rebuild on existing start/tree/settled hooks. Final tool-result `details` can preserve the exact presented question, answer, and outcome without adding a learning-memory store. If shuffled pending order must survive interruption, a small `appendEntry` in Pi's session can hold only that display state; stable order avoids this requirement. [Pi session source](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/core/agent-session.ts), [custom entry API](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/docs/extensions.md#piappendentrycustomtype-data).

8. **TUI guard and native serialization replace compatibility plumbing.** Use `ctx.mode === "tui"`, not merely `ctx.hasUI`: RPC reports UI availability but `custom()` returns undefined. Pi's own question example uses `executionMode: "sequential"`; use it instead of the original global UI mutex. Handle cancellation while waiting and inside the prompt, not only before entering it. Register the tool normally, then omit it from active tools outside TUI using `pi.setActiveTools(pi.getActiveTools().filter(...))`; retain an execution-time guard. Learners use normal text when the tool is unavailable. [Official question example](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/examples/extensions/question.ts), [mode behavior](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/docs/extensions.md#mode-behavior), [active tools API](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/docs/extensions.md#pigetactivetools--pigetalltools--pisetactivetoolsnames).

9. **One active schema is cheaper than two; registration alone is not schema exposure.** Active tools populate agent tool definitions; their descriptions and parameter schemas contribute to requests. Two original tools also add lengthy duplicated descriptions and guidelines. Prefer one short schema: question, optional context, optional stable-ID choices, optional choice key/explanation, and assistance context. Free text without choices may use the same capture tool when useful, but needs no deterministic answer key. Keep multi-select and shuffle out until needed. The existing runtime supplies a custom system prompt, so do not assume default-prompt `promptGuidelines` are automatically included; place essential behavior in concise tool description and the learn skill. No quantified token or subscription savings were measured. [Active-tool implementation](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/core/agent-session.ts), [tool definitions and prompting](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/docs/extensions.md#custom-tools), [runtime](../../../learning/runtime.py).

10. **Deterministic feedback need not add a classifier call.** Standard flow is one model response creating the question/tool call, local waiting and feedback, then the normal automatic model continuation after the tool result. A plain conversational question likewise needs a later model response after the learner replies; a tool does not inherently save that response. Pi supports `terminate: true` only when every finalized result in a batch opts in; this can omit immediate continuation, but delays adaptation and learning-record updates until a later turn. Prefer normal continuation initially, with concise tool results and no nested model calls or duplicate `sendUserMessage`. Feed actual answer/assistance to the existing learning-save workflow; do not change its schema. [Agent loop](https://github.com/earendil-works/pi/blob/v0.85.1/packages/agent/src/agent-loop.ts), [early termination](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/docs/extensions.md#custom-tools).

11. **Dependencies are already supplied by Pi.** Use `@earendil-works/pi-coding-agent`, optional UI components from `@earendil-works/pi-tui`, and `Type` from `typebox`. Installed Pi aliases the originals' `@mariozechner/*` and `@sinclair/typebox` imports, but new code should use current names without shims. The checked-in official v0.85.1 extension documentation matches installed documentation byte-for-byte. No new npm workspace, provider client, subagent package, or tmux dependency is needed. [Extension loader](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/core/extensions/loader.ts), [Pi package](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/package.json).

12. **Provenance favors a fresh implementation.** The original pinned tree contains no LICENSE/COPYING file or license header on these three files; its README explicitly invites copying pieces but does not state a standard license. Pi v0.85.1 has an MIT license. Record the original as design inspiration; implement against Pi's public API, preserving Pi's copyright/license notice if substantial official example code is copied. [Original pinned tree](https://api.github.com/repos/amosblomqvist/learn/git/trees/7cfd8942f82ab9476e63572387e1fe9bcea5082c?recursive=1), [original README](https://github.com/amosblomqvist/learn/blob/7cfd8942f82ab9476e63572387e1fe9bcea5082c/README.md), [Pi license](https://github.com/earendil-works/pi/blob/v0.85.1/LICENSE).

## Minimal change surface

`learning/pi.ts`: register the tool, expose awaited mirroring to it, and extend branch projection. Add `learning/quiz.ts` only if the prompt/rendering code benefits from separation; no second extension loader is necessary. `learning/skills/learn/SKILL.md`: brief guidance about optional use, independence, and normal tutor evaluation of free reasoning. `learning/README.md`: explain input behavior without adding learner commands. Add focused tests in the existing `tests/learning/` convention; retain the existing learning-memory schema and publisher.

## Meaningful acceptance checks

- With a paused publication promise, the dialog must remain unopened; when it resolves, the Markdown question/options exist and contain no key/explanation.
- After selected choice, free text, explicit uncertainty, skip, and cancellation, verify distinct recorded outcomes; only exact supplied choice matches receive deterministic grading. Assisted success is never labelled independent recall.
- Rebuild the same selected branch after restart/tree navigation: each question/result appears once, ordering and answer labels match the shown options, and unanswered work stays unanswered. If shuffle is implemented, force a non-identity order and test interruption as well as completion.
- Batch two question calls to verify one prompt at a time; abort a waiting/open prompt and ensure no false answer or leaked dialog remains.
- In print/JSON/RPC, inspect active tool names and ensure the TUI tool is absent; ordinary conversational input still works. Verify registration with the actual launcher rather than assuming `--tools` excludes or includes extension tools.
- Local mocks prove event/projection behavior; one manual TUI/Obsidian session proves visible timing and keyboard flow. No model calls are required for deterministic tests. Compare active schema text/bytes before any claim about lower token usage.

## Confidence

High for pinned source behavior, installed API compatibility, event ordering, active-tool control, and local grading semantics: checked official documentation, source, and current repository files. The recommended architecture is an inference from those contracts. No integration was implemented or executed; no provider/model calls, vault edits, or configuration changes were made.

## Gaps

Actual Obsidian repaint latency, terminal abort behavior of a new prompt, and launcher tool activation need implementation acceptance checks. Exact subscription impact depends on model, request payloads, caching, and follow-up behavior; source inspection cannot establish a percentage saving. Scientific correctness of generated questions and semantic grading remains a tutor/source-verification responsibility.
