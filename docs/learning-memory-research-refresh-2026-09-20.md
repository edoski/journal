# Learning-agent memory: research refresh

Checked 2026-09-20. Read the existing [source audit](learning-agent-memory-2026-sources.md) and [advanced-options note](learning-advanced-memory-options-2026.md), then checked primary sources live. This is an external-evidence review, not an implementation audit. Dates come from the sources. No runtime behavior changed.

## Verdict

Recent evidence favors recoverable evidence, explicit state semantics, selective retrieval and evaluation of the agent's resulting decisions. It does not establish a universal memory hierarchy, serialization format or retrieval backend. The strongest lean improvement is to make the relationship between evidence, current judgments and the agent's selected context precise; additional memory machinery needs a demonstrated task benefit.

## Findings

1. **Hierarchy should preserve distinguishing evidence.** [xMemory, first submitted February 2; inspected v4, May 12, 2026](https://arxiv.org/html/2602.02007v4) separates messages into segments, extracts memory components, and organizes them into revisable groups. Its principle is to isolate facts and small updates before aggregation; repeated summary compression can blur decisive differences. It reports improvements on LoCoMo and PerLTQA, with added construction cost that may not pay off when few queries follow ingestion. Its Fano-based routing bound depends on explicit assumptions; it does not prove this architecture universally superior. A curriculum prerequisite graph, a memory abstraction hierarchy and reasoning decomposition remain different design choices.
2. **The retrieval interface can matter as much as the index.** [ReFind, August 13, 2026](https://arxiv.org/html/2608.12888v1) combines iterative lexical queries with adjacent turns, session ranking, time filters and avoidance of already searched sessions. Ablations support these controls over plain repeated BM25. Its strongest LongMemEval results use only 50 S questions and 15 M questions; repeated runs measure execution variation, not uncertainty across the full benchmark. Several comparisons reuse prior results rather than rerunning every system with matched tool budgets. This supports testing evidence expansion and query reformulation before assuming that vectors or a graph are necessary. This does not establish universal lexical superiority.

3. **Encoding must preserve the relationships later decisions need.** [GroupMemBench, May 14, 2026](https://arxiv.org/html/2605.14498v1) shows ingestion failures from dropping speaker identity, mixing speakers and replacing specific evidence with broad topic labels. Its worked example contrasts successful preservation of actor/counterparty relationships with unsuccessful compression. The synthetic English workplace dataset is not a learning-system trial. Transferable hypothesis: preserve who said or did what, when, under which assistance/conditions, and where the original evidence lives. Summarizing an assisted correct answer as “understands the concept” destroys a distinction no later retriever can reconstruct unless the source remains available.

4. **Durable memory and the context shown to the agent should remain separate.** Anthropic's [Managed Agents engineering report, April 8, 2026](https://www.anthropic.com/engineering/managed-agents) separates durable session events from arbitrary context transformations and exposes positional event retrieval. The reason is recoverability after lossy compaction. Applied here, an assessment or compact teaching packet should be a projection with source references, not the sole surviving record. The report does not imply unlimited transcript retention: the relevant principle is deliberate retention and recoverability of the evidence the system promises to support.

5. **Typed state helps selectively; more structure can hurt.** [Context Compilation Architecture, September 1, 2026](https://arxiv.org/html/2609.00759v1) compiles prose into explicit rules, output requirements, tools and data information, then uses verification and correction. It improves rule-dense CL-bench tasks across tested models, but pure CCA trails direct prompting overall on its LongBench-v2 probe: 53.88% versus 57.85%. Its adaptive variant improves the aggregate; schema coverage and judge dependence remain limitations. This supports small, decision-specific fields and deterministic checks where the task has explicit invariants. It does not justify forcing exploratory explanations, uncertain learner understanding or every teaching turn through a fixed procedural state machine.

6. **Modern model capability can reduce necessary instructions.** Anthropic's [July 24, 2026 context-engineering report](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models) says it removed over 80% of Claude Code's system prompt for newer models without measurable loss on its coding evaluations. It recommends expressive interfaces, simple tool descriptions and progressive disclosure. This is a first-party engineering result with model/task limits, not an independently reproduced universal ratio. The lean inference is to remove duplicate explanations and load detailed evidence when needed, while retaining domain-specific invariants that the model cannot infer safely.

7. **Evaluate remembered behavior, including when memory should stay unused.** [Anthropic's January 9, 2026 agent-evaluation guidance](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) recommends evaluating outcomes, repeated trials, isolated state and balanced cases in which a behavior should and should not occur. This does not establish educational benefit. Local evaluation must also examine whether memory changes the next teaching decision appropriately, rather than grading only retrieval overlap or an agent's confident self-description.

## Lean design implications

These are engineering proposals derived from the evidence, not requirements established by any single paper.

**Make evidence coverage explicit.** Distinguish evidence that exists, evidence returned to the agent, evidence the agent claims to have reviewed, and evidence supporting a particular judgment. A pagination boundary or omitted source must remain visible. Publishing an assessment must not silently declare later unseen evidence reviewed. Conversely, the maximum supporting observation is not necessarily the review boundary: an agent can review contradictory evidence without citing it as support for the chosen claim. Keep enough revision/coverage information to reject stale writes and mark interpretations pending when relevant new evidence appears.

**Give judgments a bounded evidence path.** A compact packet can carry the current task, relevant constraints, current learner interpretation, unresolved evidence, and IDs for deeper reads. When it includes a judgment, either include its essential support within the budget or expose an explicit fetch route and incomplete-coverage marker. Scope, source authority, time validity and correction status should determine eligibility before relevance scoring. Reserve context for the evidence needed to challenge the judgment, not only evidence confirming it.

**Use existing hierarchy as navigation.** Start with topic/task overview, selected current state, then relevant attempts or source passages. Compute well-defined dependency paths deterministically. Do not introduce extra agents, a second ontology or recursive summaries just to call the architecture hierarchical. Promote reusable teaching procedures only when they have clear conditions, outcome evidence and a way to be revised; an agent's self-reflection is a hypothesis about effectiveness.

**Measure the full decoding cost.** Remove duplicated and irrelevant fields before considering a custom notation. Count actual tokens for deployed models; include comprehension errors, extra reads and repairs. Compact syntax alone does not establish efficient teaching. This is a measurement proposal, not a claim that one serialization is universally superior.

**Test consequential cases.** Include a newer contradiction after a paginated read, omitted/cross-topic support, corrected preferences, unknown versus contradicted understanding, assisted versus unaided success, irrelevant past failures, missing source evidence, interrupted-session continuation and bilingual paraphrases. Compare current behavior with one proposed change under the same evidence and token budget. Measure unsupported judgments, appropriate abstention, correction fidelity, teaching choice, tokens and latency; keep human learning outcomes separate from agent correctness.

At the reported current scale, a vector database, learned latent-memory encoder, global knowledge graph, background curation daemon or numeric mastery model is not supported merely by the cited successes elsewhere. Small size does not rule out useful semantic retrieval or relational planning; demonstrated missed queries and decision errors, rather than record count alone, should decide.

## Storage, retrieval and model-visible representation

These are separate decisions: the canonical state model defines meaning; the backend persists it; indexes locate candidates; the context builder selects evidence; the wire format presents that selection to the model. JSON files can represent graph edges, and a relational database can return JSON or Markdown. Replacing the backend while sending the identical complete model request produces identical input-token counts for the same tokenizer. It can improve storage latency, integrity or query operations without changing agent understanding.

The table gives architectural tradeoffs, not a benchmark ranking.

| Option | Concrete advantage | What it does not establish | Lean decision |
| --- | --- | --- | --- |
| Typed JSON files | Inspectable snapshots and straightforward structured validation; appropriate when current operations are small and known. | JSON supplies neither retrieval semantics nor transaction coordination by itself. | Keep if measured operations remain simple and fast; fix state semantics independently. |
| Relational SQLite plus FTS5 | Transactions, joins and indexed filters can combine scope, revision, evidence links and lexical search in one local store. FTS5 provides BM25, phrases, prefixes and proximity queries. | SQL does not understand a learner or make a retrieved packet smaller automatically; FTS is not semantic similarity. | A credible first backend change when cross-record operations, consistency or search justify it. |
| Vector or hybrid retrieval | A semantic candidate channel can recover paraphrases lexical matching misses; hybrid combines channels. | Similarity does not establish source authority, temporal validity or truth. A vector index is not the canonical learner state. | Compare lexical, dense and hybrid on missed local queries before choosing a service or database. |
| Graph representation | Explicit typed edges support dependency paths and evidence chains. | A graph database is not required to represent edges; inferred relations are not validated prerequisites. | Use existing relationships; add only needed traversals and provenance. |
| Markdown | Readable narrative, explanations and links; suitable for human-facing views and source material. | Prose alone does not enforce canonical state transitions, coverage or correction semantics. | Keep generated/readable views without duplicating state ownership. |
| Learned latent memory | Encodes evidence into model-consumable continuous states, potentially reducing textual context. | It is not an embedding database or alternative file extension, and is not automatically portable across models. | Research option requiring a model integration and training/evaluation commitment. |

The SQLite claims follow its official [atomic-commit documentation](https://sqlite.org/atomiccommit.html) and [FTS5 documentation](https://sqlite.org/fts5.html). It can also query [JSON values](https://sqlite.org/json1.html); JSONB avoids repeated parsing, but most JSONB operations remain O(N). That is a local processing representation, not a compressed prompt. [Recursive SQL](https://sqlite.org/lang_with.html) can traverse trees and graphs, demonstrating that relational storage and graph-shaped data are compatible. Runtime extension availability must be checked before implementation.

For empirical retrieval comparison, [AgentIR](https://arxiv.org/html/2605.25092v1) reports different lexical/dense/fusion winners across workloads. Its cascade latency is partly derived from measured stages rather than a fresh end-to-end measurement, and judge choice changes some rankings. Together with ReFind, this argues against universal backend rankings. Neither benchmarks this application's JSON records against SQLite.

[ElasticMem](https://arxiv.org/html/2605.30690v1) is an example of genuinely different latent representation: a learned allocator and projector inject hidden states as soft memory tokens into an adapted reasoner. Its evaluation uses Qwen2.5 3B/7B and task-specific training; some QA tasks use multiple-choice transformations. Its reported latent-token counts are not interchangeable with billed text tokens in a hosted-agent workflow. Using the mechanism requires model-internal integration, not merely writing vectors into JSON.

**Wire format is a separate, bounded experiment.** JSON suits precise machine contracts; Markdown suits selected explanatory context; uniform rows may benefit from shared column headers. The [TOON project's own documentation](https://github.com/toon-format/toon) identifies uniform objects as its strength and warns that compact JSON can win on nested or irregular structures and latency. These are format-author observations, not proof of local superiority. Compare compact JSON, an explicitly labeled Markdown view and a tabular encoding on the same selected facts; include decoding accuracy and required format instructions.

**Keep interaction conversational.** The user should be able to say “continue where we stopped” or correct an assessment in ordinary language. The agent and deterministic application service should resolve scope, retrieve support and publish valid changes internally. Backend choice does not require exposing JSON, SQL, IDs, review receipts or bookkeeping commands to the user. Ask a clarification only when its answer changes the teaching decision; preserve durable pending state across interruptions. These are product design recommendations, not measured research outcomes.

**Compare complete work, not one cheap operation.** Measure time to useful teaching, model calls, tool round trips, input/output tokens, correction retries and user interruptions alongside evidence correctness. Include indexing, consolidation and embedding costs amortized over actual reuse. A smaller initial packet that causes three extra model/tool rounds may be worse; a single giant packet can waste attention. Backend-only speedups and fewer serialized bytes do not establish lower end-to-end cost or better learning. No inspected source proves one representation best across these objectives.

## Confidence

Strong: separation of recoverable evidence from selected context; source-preserving updates; scope and temporal semantics; evaluation of actual downstream behavior. These recur across independent primary research and first-party engineering accounts.

Moderate: selective hierarchy and agent-controlled retrieval as candidate improvements. Reported gains depend on datasets, controllers, budgets and evaluation methods. Weak for this application: claims that any specific format, model or backend is optimal, or that conversational recall improvements cause better human learning.

## Gaps

No cited work measures this implementation, its actual host/model combinations, Italian/English course material or this learner's retention. A local behavioral baseline and matched, held-out comparisons would settle practical retrieval/encoding choices. Retention and transfer assessments over time would be needed to establish educational benefit. This targeted refresh is not an exhaustive survey of every publication through September 20.
