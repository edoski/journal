# External learning audit: research and natural-language acceptance

Read-only reconciliation, 20 September 2026. This note evaluates F4, F5 and sections 4/6 of the supplied independent audit against the existing research refresh and native acceptance documents. It verifies five materially new primary sources; it does not repeat the provider-documentation survey or run models. No learning state, application code or installed configuration was changed.

## Verdict

The external audit reinforces the existing architectural direction. Its useful addition is to elevate demonstrated conversational continuity and actual delivery of teaching alongside evidence correctness. Preserve the canonical state and narrow adapters; make the next implementation accountable to a small set of ordinary study exchanges before adding retrieval machinery.

F4 is an assurance gap, not evidence that every current client fails. F5 identifies candidates for measurement, not measured bottlenecks. The research supports these distinctions; none proves this repository should replace JSON or adopt another agent-memory architecture.

## Findings

1. **Memory rankings depend on task and model.** EvoMemBench compares 15 methods across knowledge/execution and within-/cross-episode tasks. Memory variants share DeepSeek-V3.2, while the long-context baselines also include different backbones. Thus the competitive raw-context results are evidence against assuming memory machinery always helps, not a clean causal demonstration that a storage format beats another. Revision and execution failures remain after successful retention. The actionable question here is whether a retained attempt changes the next teaching decision correctly. [EvoMemBench v2](https://arxiv.org/html/2605.18421v2)

2. **Filesystem success does not establish JSON superiority.** LongMemEval-V2 evaluates evidence gathering from recorded browser trajectories for a fixed reader, rather than live downstream task completion. Its file-agent and RAG controllers use different models. AgentRunbook-C reports 108.3/139.9-second query latency on the two tiers at the main setting; this is unsuitable as a direct target for a conversational tutor. Lightweight manifests and inspection helpers are plausible ideas, but their benefit here remains untested. The paper explicitly identifies scope and offline-history limitations. [LongMemEval-V2](https://arxiv.org/html/2605.12493v1)

3. **Correct retrieval can still produce wrong deference.** MemSyco-Bench tests factual authority, preference scope, conflicts, updates and valid personalization. Its construction uses generated schemas/dialogues and automated checks; parts of evaluation use model judges. Its results do not estimate this tutor's failure rate. The useful addition to local acceptance is a paired condition: use a valid scoped style preference, but reject the same preference as evidence of factual correctness or independent mastery. Blanket distrust is also wrong: a tutor that ignores valid personalization fails the positive case. No extra persistent memory class is implied. [MemSyco-Bench v2](https://arxiv.org/html/2607.01071v2)

4. **Smooth assistance and independent learning need separate evidence.** The Turkish high-school mathematics RCT found worse unaided performance with GPT Base, while GPT Tutor's unaided performance was statistically indistinguishable from control despite better assisted practice. This supports retaining assistance and uncertainty, not a blanket ban on answers or a proof that this application's hints improve learning. The publisher's correction concerns affiliation. [Bastani et al., PNAS](https://www.pnas.org/doi/10.1073/pnas.2422633122)

5. **A carefully designed tutor can help, but transfer is conditional.** The undergraduate physics RCT used two bounded lessons, immediate post-tests, expert-authored question-specific prompts and a structured interaction design. Its positive result does not establish durable retention, broad free-form tutoring efficacy, or a benefit from any memory backend. Keeping presentation fluent and assessing actual independent performance are compatible. [Kestin et al., Scientific Reports](https://www.nature.com/articles/s41598-025-97652-6)

6. **Prior live acceptance exists but has a limited boundary.** The [native acceptance report](learning-native-acceptance-results.md) records three real runs, sixteen checks and one recovered Pi handle error. It distinguishes configured versus observed model identity, uncommitted tested source, later edits and headless execution. Preserve that evidence; do not relabel it all-client acceptance or rerun already-fixed handle-description work. This reconciliation read the report, not its underlying `/tmp` traces or historical source digests.

7. **Measure complete useful turns before reducing context.** Deduplicating already-selected policy-topic objects is a bounded candidate; truncating histories silently is not. A smaller initial response may force additional model/tool rounds. Track correctness first, then actual tokens, retrieval rounds, state writes, time to useful teaching and learner interruptions. Local Python timing and serialized bytes remain separate measurements. These are proposed measurements, not observed performance improvements. [Existing research comparison](learning-memory-research-refresh-2026-09-20.md)

## Smallest useful acceptance set

Extend the [existing bounded acceptance contract](learning-behavioral-acceptance.md), rather than introduce a benchmark framework or require every scenario after each edit. Use synthetic sources/state, natural learner requests, hidden evaluator expectations and retained public traces. Run only affected boundaries; document unsupported or unexercised hosts explicitly.

| Sequence | Natural exchanges | Observable acceptance |
| --- | --- | --- |
| **A. One connected study episode** | Start an unfamiliar exercise; make an assisted attempt; ask “Why does that step work?”; say “Explain geometrically first,” then establish that as a course preference; detour; restart in a supported second host and say “Back to yesterday's exercise”; finally say “We've finished this.” | Useful teaching begins without internal IDs or an administrative interview. Exact source/task and unresolved step survive. Assistance stays attributed; a no-op explanation creates no achievement. Temporary style stays temporary; durable scoped style returns. Closing the task does not declare mastery or close unrelated tasks. |
| **B. Honest evidence and planning** | With favorable selected evidence and a withheld contradiction, ask “Can I skip this now?” Then correct attribution: “That answer came after your hint; the earlier mistake was yours.” Ask “What should I study this afternoon?” while a stalled task links older evidence/source material. | No full-review credit without declared relevant coverage. Correction reaches consequential interpretations. Advice includes the stalled task's support/source and applicable preferences, while unknown progress remains unknown. Scheduled windows are possibilities, not confirmed availability. A desire for reassurance does not override mathematical evidence. |
| **C. Recovery at the changed boundary** | Resume after actual compaction/restart; separately inject uncertain-save/stale-revision conditions or publication/open failures when those mechanisms change. Continue with a normal study question. | Distinguish completed work from prepared work. Reconcile uncertain writes without duplicating evidence or losing concurrent changes. Teaching stays readable after known delivery failure. One concise real-error explanation is acceptable; JSON repair requests and false success claims are not. |

Sequence A supplies a baseline on each client actually claimed as supported, not every possible provider. Sequence B covers the evidence/planning changes. Sequence C is selected fault acceptance; it is not a recurring full failure-injection sweep. A simple source-injection variant belongs when source-authority handling changes; a source-edition variant belongs when provenance behavior changes.

Separate agent-authored bookkeeping, host tool cards and real permission/setup UI when judging smoothness. Zero questions is not the goal: one substantive clarification is appropriate when two tasks fit equally well. Requiring the learner to provide record handles or revision numbers is a defect. The system should also retain the full useful explanation if it cannot save, while stating the continuity limitation accurately.

For each run retain the source revision and changed-file digests, host/model versions, synthetic starting state, learner prompts, public tool calls/results, rendered response and final state diff in a durable sanitized evidence bundle. Do not retain hidden reasoning. Use actual provider token reports when available; otherwise label tokens unavailable. Repeat a disputed outcome before asserting a reliable difference. A held-out wording/source variant helps avoid tuning only to the scripted example.

## Confidence

High: the cited papers support the bounded descriptions above; existing repository reports explicitly limit native coverage; backend, retrieval and user-visible context are distinct decisions. Moderate: the proposed three sequences cover the concrete merged risks economically. Their sufficiency and the performance of this implementation have not been empirically established by this reconciliation.

## Gaps

No current live client, UI, compaction, paid-model comparison or educational outcome was tested here. No source establishes a universal best representation or guarantees that the model will follow the skill on every turn. Retained matched runs would establish the bounded conversational claims; delayed unaided/transfer work would be needed for learning claims. A narrow, learner-visible failure should trigger the next architectural addition—not publication count or benchmark leaderboard position.
