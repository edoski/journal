# Spatial visuals

Use native Mermaid for relationships and dependencies. When actual geometry makes the explanation clearer—vectors, transformations, functions or distributions—author a compact SVG and embed it in the lesson. Generate coordinates with available Python tools if useful; no extra service, maker agent or rendering package is required. Reuse an existing useful visual rather than recreating it each turn.

Pipe SVG to `scripts/learn visual --title 'Projection onto a line'`. The helper returns an absolute `path` and a Markdown `embed` relative to `.study/lessons/`; place the embed beside the explanation. Pi mirrors it into the lesson unchanged. In a desktop interface that cannot render the relative embed, use that client's normal local image display or link. Publishing identical content reuses its asset; changed content gets a new file under `.study/assets/`, preserving older lessons.

Use an SVG root with `xmlns="http://www.w3.org/2000/svg"` and a finite `viewBox="0 0 WIDTH HEIGHT"`. Supported elements are `svg`, `g`, `path`, `line`, `rect`, `circle`, `ellipse`, `polyline`, `polygon`, `text`, `tspan`, `title`, `desc`, `defs`, `marker`, `clipPath`, `linearGradient`, `radialGradient`, `stop` and `use`. Use presentation attributes such as `fill`, `stroke` and `font-size`; local `href="#id"` and `url(#id)` references work. Scripts, CSS styles, animations, external resources and embedded HTML/images are outside this static format. Keep labels readable with enough margin; choose explicit foreground and background colors so the diagram remains legible across themes. Put LaTeX in the surrounding Markdown, rather than expecting SVG text to render it.

Check the represented relationships before publishing: coordinates, scale, orientation, endpoints, signs, assumptions and labels. SVG coordinates normally increase downward; account for that when depicting mathematical axes. A clean-looking picture does not establish mathematical correctness. Inspect a rendered result when layout or complexity leaves real uncertainty; simple geometry needn't trigger another tool or model pass. Keep the response about what the visual teaches, not its generation.
