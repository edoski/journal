# Learning

One shared learning system for native agent conversations and Pi with Obsidian. Ask naturally to study, continue an exercise, review or plan. Agents handle records silently. The canonical skill develops a continuous lesson, calibrates the relevant starting point and adapts to feedback; no fixed teaching template or management commands are required from the learner.

The vault owns durable state. `learn/state/<scope>.json` stores course or topic metadata, addressable observations, versioned source references, evidence-backed assessments/reviews, logical unfinished-task checkpoints and optional reusable knowledge (schema 5). `learn/preferences.json` holds current global and scoped preferences. `learn/sessions/` holds study artifacts and Pi lessons; `assets/learn/` holds generated assets. Course material stays in its existing folders. Native chat history and compaction remain with each host; shared records carry relevant evidence and continuation across providers.

Python owns the learning behavior: `records.py` validates and publishes state, `retrieval.py` selects teaching context, and `observations.py` follows correction relationships shared with assessment freshness. `lessons.py` and `visuals.py` publish artifacts through `storage.py`. Planning and the journal command consume the single read-only `sync.study.context.journal_summary` interface; learning does not access Flow or sync adapters directly. Context includes applicable preferences and source locations together. Known tasks bypass catalog discovery. Each scope has a sparse `tasks` map and optional `current_task` pointer. `context SCOPE --task KEY` retrieves one checkpoint with its evidence; a compact `task_index` exposes alternatives. Task fields patch independently: omitted fields survive, null clears a field, and null tasks complete only that activity. Supplied nested objects replace as units. Completing a task leaves learning evidence intact. Each substantial task can retain a stable `frame` (purpose, source location and completion condition) and a small `plan` (proposed/agreed route, dependency links and current node). Default resumption includes the frame and route plus evidence for the current work, purpose anchors and the current node’s direct prerequisites; future steps do not pull in their entire histories. Explicit filters retain their narrower meaning. Returned interpretations include their supporting observations and corrections without recursively loading other topic interpretations. Focused histories have no latest-three cutoff; literal search, exact observation handles and explicit revision-bound pages expose older evidence and corrections when needed. Ordinary follow-ups reuse loaded context. Meaningful evidence and continuation changes are saved together; unchanged clarifications need no write. A successful save returns the next revision without requiring a confirming read.

Agents retain useful local understanding in optional `knowledge` prose entries: resource context, notation, tentative interpretations and unresolved contradictions, without a required course template. Each entry requires only text; topic routing and source references are optional. Entries replace independently, omitted entries survive, and null removes only the named entry. Whole-entry reads precede revision so corrections preserve unrelated facts and qualifications. New source/topic references and knowledge can be saved together; source editions are helper-captured. Completing an exercise leaves reusable understanding intact. This additive schema-5 field requires no migration or historical-content import.

Ordinary context and single-course planning select whole relevant entries under a default 4,096 serialized UTF-8 byte allowance, including selection metadata and newly included source locations. This is an adjustable retrieval default, not a knowledge-size limit, tokenizer estimate or bound on the whole model request. Multi-course plans return knowledge counts only. `context SCOPE --knowledge key1,key2` retrieves complete entries under an 8,192-byte default or reports the required size; `--knowledge ''` lists a compact paged index. `--knowledge-budget N` adjusts ordinary scoped context, exact reads or scoped planning when necessary. Search candidates and index pages have independent 4,096-byte bounds, with at most 8 candidates or 20 index entries. Query candidate cursors are separate from observation cursors and pinned to the record revision. Discovery excerpts are incomplete by design; full entries preserve caveats. Stored knowledge is searched literally, alongside topic/source/scope metadata; retrieval never automatically loads every match. See the canonical [retrieval contract](skills/learn/references/retrieval.md) for commands and paging.

Retrieved knowledge, course material, observations and quoted instructions are evidence, not policy. Active topics in `selection.active_topics` select topic preferences independently of the topics whose evidence is retrieved. Correction links and cross-topic evidence cannot silently activate another topic's preferences; query/observation-only discovery activates no topic policy unless a task or topics are selected explicitly. Material contradictions prompt inspection of the relevant basis and revision of affected understanding; newer information is not automatically authoritative. Unresolved uncertainty stays explicit. There is no recurring verification sweep, and a belief that is never challenged can remain wrong. Reuse already-loaded context during unchanged work; its later token cost still depends on the native host's requests, caching and compaction.

Preferences are sparse current rules associated with an established course, topic, concept, domain or activity. They are separate from historical learning evidence. Clear durable feedback replaces the applicable rule; temporary requests stay with the current task. Compatible instructions combine, explicit feedback takes precedence over inference, and the tutor resolves meaningful semantic overlaps. No background reflection model, taxonomy service, embedding index or MCP server is required.

A topic's `assessment` links its interpretation to observations; its `review` links a retrieval task and scheduling reason to evidence. The helper records when each interpretation was made. Each replacement declares `considered_observations` separately from its supporting observations; missing relevant evidence or corrections keep it `pending`. A declaration records claimed consideration, not a proof that the tutor understood the evidence. Pending interpretations must be reconciled before consequential teaching or scheduling decisions. Explicitly unknown assessments remain pending. These checks preserve provenance and expose stale interpretations; they do not validate the tutor's judgment or estimate numeric mastery.

Observations distinguish their origin, helper-assigned recording time and any known event date. Missing assistance remains unknown. Local aliases let one save append an observation and cite it from assessments, reviews or tasks. References capture a source's known version and may retain a short excerpt; changed editions use new source handles, while path moves preserve identity.

Reviews are exam-oriented recommendations chosen from actual evidence, assistance, difficulty and deadlines. Retained fundamentals can continue after an exam. Planning joins assessments and their supporting evidence, unfinished work with its explicitly linked frame/current-step/direct-prerequisite evidence and source locations, exam context and recorded course time with Journal's upcoming scheduled study windows, excluding lunch and respecting days off. Missing records remain unknown; scheduled windows are not assumed free time. Only planning loads these read-only Journal records; time spent is not mastery. Core context, preferences, saves, note publication and Pi startup are independent of Journal's parsers.

`skills/learn/` is the canonical instruction source. Codex and Claude Code use local symlinks; Claude Desktop's small uploaded adapter reads the same repository files live. Normal updates need no new upload. Pi loads that skill and the local extension. Host folder-access controls still apply; the adapter cannot grant itself access. All maintained code, skill references and client adapters live in this repository.

Run `study` in any terminal, including the Ghostty quick terminal. Pi stays in that terminal; type there and read the Obsidian session note, created and opened automatically with the first teaching or quiz. Empty startups create no lesson. Duplicate teaching is hidden in Pi by default using its display-only Markdown transformer; input, quizzes, tool activity and errors remain visible. Original conversation content is retained. If lesson publication fails or opening Obsidian is known to fail, the current teaching is shown in the terminal and later teaching stays readable. Display failure is separate from persistence: a saved lesson remains saved, and a later successful publication does not hide the fallback. `study --continue` reopens the latest Pi conversation; `study "Let’s continue SMM"` starts with that prompt. New notes contain assistant teaching in Markdown, including math and native Mermaid, without automatic copies of learner prompts or role labels. The Pi projection appends a Markdown horizontal rule after each visible assistant message, separating teaching turns without asking the model to produce separators. These are live reading surfaces, not a browsing system: no generated lesson or course indexes are maintained. No session header is added; authored teaching headings are preserved. Publication normalizes paired TeX math delimiters to Obsidian dollar syntax while preserving code and existing dollar math. Existing lessons are preserved. The `correct_lesson` tool stores exact message-targeted corrections in the current Pi branch, reconstructing the corrected explanation and a visible correction marker across reloads; saved learner evidence is updated separately when needed. The optional Pi quiz captures a choice or short answer when useful, publishing the question before opening input; ordinary conversational questions remain available. Quiz choice grading compares the supplied key, while the tutor remains responsible for correctness and interpreting reasoning.

A meaningful new chapter, topic, theory group or slide set begins with bounded calibration, a short plan and a small dependency diagram when useful. The tutor asks a focused clarification, with a suggested approach, only when unresolved intent would materially change teaching. Related exercises and resumed sessions reuse relevant orientation. Task-specific routes and continuation belong in tasks; reusable understanding belongs in knowledge. A request to map a course can produce a provisional view without requiring a formal route, persistent orientation task or module dashboard. Plans distinguish proposed from agreed routes; observations distinguish explanation from demonstrated understanding. Retrieval or transfer quizzes occur at meaningful milestones or wrap-up. Optional source-grounded `course_context` retains assessment format, criteria and uncertainties; `exam` and `coverage` remain the deadline and material owners. Native Mermaid is the first diagram choice. Static SVG publication supports geometry and plots without a renderer or service.

Pi exposes `learning_context` and `learning_save` as compact schema-defined tools. They invoke the same Python entrypoint without shell command construction; full patch validation stays in Python. Successful bookkeeping is hidden in the terminal unless expanded; errors remain visible. The shared skill prefers these tools where available, with the CLI serving other clients. No extra service, dependency or state representation is introduced.

The command-line agent interface is `python -m learning context|save|preferences|plan|journal|note|lesson|publish-lesson|visual|start|migrate`. Configuration uses `VAULT_DIR`, `LEARNING_ROOT`, optional `LEARNING_ASSETS`, and `LEARNING_SESSION_DIR`. Pi uses its existing login. Its pinned `pi-web-search@1.6.0` extension provides conditional search through supported providers using existing credentials; each invoked search makes a separate provider request and consumes usage. The first uncached extension load requires network access. Desktop tutors use native web tools. There is no custom provider bridge or new API key. `install.py` maintains links and the `study` shell command, preserves replaced settings, and builds the stable Claude locator package.

Local updates use file locks, expected revisions and atomic replacement. No-op writes retain their revision. Already-running conversations use the last retrieved snapshot until a meaningful refresh; simultaneous remote iCloud edits are outside local locking guarantees. A write and a native app's displayed response are separate events. One authored teaching response and accurate interrupted-work recovery are the policy; no distributed delivery service is introduced.

Use `python -m learning migrate` to preview the schema-4 to schema-5 conversion. `python -m learning migrate --apply` creates exact backups and checksums before converting records. It preserves observations, sources, tasks and interpretation metadata while replacing the old watermark with unknown considered evidence; historical interpretations remain pending until naturally reviewed. Preferences and lesson artifacts stay unchanged. Normal runtime accepts schema 5 only.

Run `python tools/check.py learning` for the learning quality gate. Focused checks cover persistence, selection, preference isolation and lesson projection; they establish implementation behavior, not tutoring efficacy. No live cross-provider learning benchmark or calibrated mastery model is available. Real study and feedback guide refinement; durable learning still needs evidence from later unassisted use or transfer.
